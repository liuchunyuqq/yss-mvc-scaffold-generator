# 验收驱动开发

`acceptance-policy.yaml` 是 project-instance 默认执行策略。生命周期注册表保留阶段、资产和稳定 ID 的导航职责；其中旧批准门禁以及 skill 的旧批准前置条件仅用于 schema v1 历史记录。新任务使用 checkpoint schema v2，不写批准记录，不通过伪造 approved 兼容旧门禁。模板源仍按模板维护规则执行。

## 连续执行

用户要求实现或修复时，自主推进到验收完成；要求分析、方案或审查时保持对应范围。先读 CONTEXT.md、目标和已有工程规范。质量基线定义一次，需求只补业务验收条件；给验收条件稳定 ID，并将其映射到切片、检查和整体结果。普通命名、分层、测试组织、缺陷修复不询问用户。局部小改动可用一个切片，不创建空 Spec、原型或 API 文档。

按需分析、维护 Spec / OpenAPI / 数据约束并拆分切片。已有对外接口兼容性和工程约束仍有效；接口基线更新由 AI 在授权范围内同步消费者与测试，不以人工 Freeze 为前置。合同是可执行技术计划，校验状态使用 validated，包含目标、验收条件、路径、依赖和必要检查；可读、当前、无阻塞后直接执行，不经过 ready-for-human。ready-for-agent 由编排器计算，不代表用户批准。

每个切片由实施者完成相关检查，再由不同实例执行独立 Review。Review 发现问题后实施者自动修复，复查相关问题及受影响行为，通过后继续下个切片。全部完成后执行整体 Review 与集成验收，核对每条需求、跨切片一致性和未关闭问题。不能修改验收条件来消除实现失败。

## 提问与自主纠偏

仅当业务歧义、需求冲突、范围扩张或必需外部信息缺失时提问，附具体分歧、影响和推荐方案。暂停依赖答案的工作，继续独立工作。工具失败和未知策略先诊断，不把工程错误变成批准请求；无进展时报告具体阻塞。

violation 自动修复；stale 先刷新真实受影响输入；drift / new_impacts 先判断是否仍在目标授权内，范围内更新计划、契约与必要验证后继续。不得继续使用过期契约，也不得仅凭新影响标签要求用户确认。变量改名不等于业务术语变化；稳定业务术语变化先同步 CONTEXT.md，确有语义歧义才询问。

## 验证与审查证据

检查按实际依赖变化选择。首次使用或环境变化检查技能环境；开发中运行相关检查；交付时执行必要集成验证。Maven package 已执行的 test / validate 不机械重复。证据保存命令、退出码、执行时间、环境标识和输入摘要，任一相关输入或环境变化即失效；无关文件变化不使所有证据失效。

Reviewer 只读检查代码，报告包含范围、实施者与审查者身份、验收 ID、候选内容摘要、检查证据和 findings。普通切片用范围内文件摘要，不强制 candidate.bin、双 Reviewer 或全仓打包；正式模板发布保留其独立规则。摘要只能证明身份，不能证明代码正确；机器通过也不能替代独立语义审查。判断性建议不是新硬要求。修复无进展时诊断原因，不按固定轮数请求用户批准。

checkpoint 在切片完成、实际阻塞、交接和交付时集中更新。开发完成要求所有切片与整体审查通过，验收 ID 完整覆盖、相关检查成功且无未关闭缺陷。开发完成不等于部署或对外发布；外部动作消费已有用户授权，超出范围才另行确认。

## 兼容与迁移

v1 checkpoint 与 approval-record 保留只读验证，不批量重写。恢复旧任务时根据真实资产重建 v2 记录，保留 legacy_ref；不能把旧批准直接翻译为新验收通过。MVC 环境恢复只恢复 skillUtils，治理迁移使用专用预览/应用入口，保留备份；用户定制冲突必须合并，禁止覆盖。

旧 MVC 项目先用当前插件 `scripts/migrate_governance.mjs --project-root <目录> --dry-run` 查看文件清单，应用使用 `--apply`。有受管摘要时只替换未改动文件；早期项目没有受管摘要时可用 `--baseline-dir <旧发行生成文件目录>` 比对，未知定制输出 conflicts，应用不会写入任何项目文件。不能把当前定制文件当作旧发行基线来覆盖。缺失 Profile 指针补默认，非默认指针交由合并；已知旧机器配置只定点更新旧流程名和连续的 validate/test/package 命令，保留其他字段。治理迁移完成后再用当前插件 `restore_environment.mjs --project-root <目录> --upgrade` 更新相邻 skillUtils；最后执行项目 `check-agent-environment` 和 `verify-governance`。已有用户授权内可以连续执行这些步骤，不额外申请流程批准。
